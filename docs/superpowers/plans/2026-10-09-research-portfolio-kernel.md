This specifies B2c from the approved research-execution-and-portfolio plan. No indicator/strategy/risk-policy rewrite and no exchange orders.

## Boundaries and API

- Main module `app/backtesting/research/portfolio_simulator.py`, at most a few focused helper modules, with tests. Expose a deterministic incremental API receiving a complete ten-symbol timestamp batch of validated closed minute candles, observed funding events, then eligible passed B1 signals via a plan-builder callback. The callback takes the exact current `research-portfolio-view.v1`; production will call persistent PHP B2b. Kernel tests use explicit synthetic research-plan fixtures, never imply these fixtures are authorized canonical plans.
- Use Decimal for balances/prices/cashflows; reuse established PHP-compatible canonical JSON for portfolio hashes at the protocol edge, with explicit finite conversion and cross-language tests. Read actual ResearchPlanBuilder output from the research-plan-worker worktree and keep integration adapter narrow if that schema changes. Expose cashflow/trade/rejection/event sinks rather than growing an in-memory full-history ledger.
- Initial wallet100000 USDT; fixed symbol order BTC,ETH,BNB,XRP,ADA,DOGE,SOL,LTC,LINK,AVAX. All symbols share one wallet/risk/concurrency/exposure clock. No per-symbol capital clones. Support explicit training/test subsets only when declared before run; no unseen symbols.
- Source data and assumptions are supplied/validated by caller. Kernel validates monotonic full batches, exact one-minute coverage, positive finite OHLC bounds, no future or duplicate signals and immutable run assumptions. Never silently forward-fill gaps. It does not download, load user env, read holdout, write to exchange or build indicators.

## Clock and conservative fill model

- A bar describes `[open_ms,open_ms+60000)`, its full range/close available only at its ending boundary. At that boundary process pre-existing pending/positions through this bar, settle events/costs and mark equity, then request/admit signals available at the boundary. Thus a new plan cannot fill from the candle that produced it. Frozen same-time ordering follows the approved universe.
- Limit entry at declared plan price, no favorable improvement, no partial-fill/queue-certainty claim. Touch on a later bar only if its entire interval is within the plan's valid entry lifetime. At TTL90sec, the second minute straddles expiry: do not turn an ambiguous low into a fill. Emit counted ambiguity/expiry events and release its pending reservation at expiry before later admission. Do not extend entry eligibility to cancel120sec.
- On a fill candle, stop/liquidation takes priority whenever its range could trigger; target-only within the fill candle is not assumed reachable after entry unless chronology is provable. Count ambiguity rather than optimistic same-bar profit. Existing positions: stop vs target overlap chooses worse outcome; gap through long stop uses min(open,stop); target fills no better than target. Costs apply once, separately from gross exit-price PnL.
- Force close by holding deadline and before UTC midnight. Use latest fully known eligible close as an explicitly labeled research settlement, with adverse taker costs; do not invent an intrabar point. Read CanonicalHoldingBoundary actual semantics (midnight deadline may be 23:59:59), and handle deadline within a minute without admitting exposure to observations after that deadline. At study end, close remaining positions at last known eligible close with explicit research_end reason, expire pending, and reconcile; never leak next-phase prices.
- Funding events retain exact milliseconds. Declare a conservative path-ambiguity policy when an event lies inside a candle whose fill/exit time is unknown: for a long adverse positive charge choose possible exposure, for a favorable credit require certain exposure. Settlement uses a declared past-known close mark proxy when a verified mark observation is absent, never that minute's future close. Exact-boundary funding is settled on positions already open immediately before the boundary, before new entries. Missing funding coverage is caller/kernel invalid/inconclusive, not zero; empty explicit observed-only windows cannot be mislabeled certified complete. Log rate, proxy, timestamp, amount and ambiguity.
- Liquidation is a declared isolated-margin proxy using actual final_leverage, entry, MMR and liquidation-fee hypotheses, not historical exchange truth. For long linear USDT contracts a transparent approximation is entry*(1-1/leverage)/(1-MMR), with charges/limitations documented; leverage1 may imply zero boundary. Use worse outcome if stop and liquidation can both occur. Never label the proxy exchange-certified; test stress cases.

## Portfolio/risk parity and accounting

- B2b sizes/admit from current equity/available margin and authentic unchanged policy. Kernel independently rejects malformed plans and violations: cap250, min declared notional, quantity/tick grids, actual leverage<=2, max4 pending+positions, exposure<=equity, risk5%, daily loss min(.06*equity,30), netR>=1.3, correct hash/source/signal identity and TTL/holding bounds. Do not fake CanonicalOrderPlan types.
- Actual repository lifecycle verified: `InMemoryCanonicalPortfolioReservationStore::assertSnapshotIncludesCommittedState` sums **filledRisk+residualRisk until close**, not just pending risk. Full fill at limit maintains planned total stop risk; release it only on close/expiry (cancel only releases unfilled risk). Entry notional stays committed at entry price for the admission exposure snapshot; equity uses current available marks.
- Mirror `CanonicalPortfolioAdmissionEngine`: consumed daily allowance = max(-realized net PnL since UTC day start,0)+max(-aggregate unrealized net PnL,0)+reserved risk; then candidate total stop risk must fit remaining. Do not simplify away reserved risk after entry or sum each negative symbol separately. Golden tests must cite values matching PHP policy/engine fixtures, not just self-confirm the Python formula.
- Wallet updates from entry/exit fees, separately declared spread/slippage, signed funding and gross realized PnL; equity=wallet+marked unrealized PnL. Margin locks affect available balance but not wallet/PnL. Prevent double charging provisions: funding provision is reserved/planned risk, actual funding is its cashflow, never both fees. Plan cost rates/proxies must be frozen and identical for simulation and NetR. Entry/target prices cannot be silently worsened and also charged spread/slippage twice.
- Track incremental peak equity and marked drawdown (including unrealized), risk/exposure maxima, rejected reasons and ambiguity counts. Completed trade records carry all identity hashes, decision/fill/exit boundaries, quantity, prices, gross/net PnL, fees, funding, spread/slippage and exit reason. A trade remains attributable to its variant/source even on failure/zero activity. Daily resets do not reset cumulative wallet or erase a loss.
- Determinism tests compare uninterrupted feeding with the same stream partitioned into chunks; no restart/resume claims absent a validated state serialization format. Source end/count and explicit finish are required; process exit alone is not campaign completion.
