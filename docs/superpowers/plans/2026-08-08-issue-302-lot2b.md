# Issue #302 Lot 2B — Recovery/read certification implementation plan

## Goal

Complete the exact Lot 2B boundary documented in
`trading-app/docs/trading/canonical-trade-path-lot2a.md`: preserve one immutable
canonical identity per symbol through persisted orchestration, restart/replay,
order/fill/position recovery, analytics, outcomes, and exports. Never infer modern
identity from symbol, time, legacy profile, or JSON `extra` fields.

Issues #303 and #304 remain out of scope. Published modern contracts remain
fail-closed until their independent blockers are removed.

## Invariants

1. A persisted modern set stores a validated `CanonicalTradingIdentity` snapshot;
   create, patch, read, prepared payload, dispatch, retry, and replay preserve it
   byte-for-byte.
2. A request identity is unbound at request scope and is rebound immutably for each
   concrete symbol before worker or Messenger fan-out.
3. Recovery accepts identity only from an exact typed durable predecessor. Missing
   or conflicting identity is classified explicitly and rejected for modern data.
4. External order IDs may link records only when venue, market, symbol, side, and
   canonical contract match.
5. Analytics and exports expose structured identity plus an explicit
   `canonical`, `legacy`, or `incomplete` classification. They never reconstruct
   fields from profiles, timestamps, symbols, or `extra`.
