# Paper plan rejection diagnostics

The Paper replay command accepts an optional path for a private NDJSON file. It creates the file exclusively with owner-only permissions, then records one small JSON object per expected canonical plan rejection. A reused command closes and resets the writer on either success or failure. A file open/write failure fails the command explicitly; no successful completion proof is printed for an incomplete diagnostic.

The source passes Paper cell, run, event, config, symbol, and side identity into plan construction. At the existing expected-exception catch, a Paper-only writer records one of the six established reason codes. For zone rejections it records only candidate, anchor, ATR, tick and zone policy numeric inputs. Exact quantized lower, upper, and entry bounds are unavailable in this catch and are explicitly represented as null. No complete market payload, exception text, credentials, or stack trace enters the file. The writer never changes a plan decision or canonical contract. Unexpected exceptions still propagate.

The diagnostic is outside the replay journal, checkpoint, completion JSON, and business hashes. The modern end-to-end test consumes one accepted trigger through the in-memory coordinator with the writer on and off, comparing the resulting decision and business facts. It does not run the full CLI replay, exercise a rejected modern trigger, or prove a Doctrine journal checksum: the in-memory store supplies a constant checksum. Unit tests cover refusal redaction and correlation, inactive mode, expected and unexpected exceptions, private exclusive file creation, and failure on IO errors. The command test verifies reset after failure; it does not exercise reuse after success.
